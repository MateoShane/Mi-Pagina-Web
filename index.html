Proyecto principal

Cluster Proxmox VE con Ceph sobre Hyper-V

Diseño e implementación de un cluster de 3 nodos Proxmox VE virtualizados sobre Hyper-V. Configuré almacenamiento distribuido con Ceph: creación y gestión de OSDs, pools de almacenamiento y volúmenes RBD (RADOS Block Device) para alojar los discos de las máquinas virtuales. Realicé pruebas de conectividad, administré el cluster de forma centralizada y desplegué máquinas virtuales Linux y Windows.

3OSDs Ceph

Tecnologías

Proxmox VE Ceph RBD Hyper-V Linux Windows Server SSH Virtualización Redes TCP/IP

Cómo lo monté

  1. Preparar el host Hyper-V

    Tres VMs con virtualización anidada activada, switch virtual y suplantación de MAC para que las VMs internas tengan red: Set-VMProcessor -ExposeVirtualizationExtensions $true

  2. Instalar Proxmox VE

    Instalación en los tres nodos con IP estática, hostname y resolución de nombres entre ellos.

  3. Crear el cluster

    Cluster creado en pve1 y nodos unidos por SSH: pvecm create lab · pvecm add pve1

  4. Desplegar Ceph

    Instalación de Ceph, monitores y managers en los nodos, con red dedicada para el tráfico de réplica.

  5. Crear OSDs y pool

    Un disco dedicado por nodo como OSD y un pool replicado con size=3 y min_size=2.

  6. Almacenamiento RBD

    Pool añadido como almacenamiento RBD del Datacenter para alojar los discos de las VMs.

  7. Desplegar y probar

    VMs Linux y Windows Server sobre RBD, pruebas de conectividad y comprobación del estado del cluster.

Incidencias resueltas

KVM no disponible

Virtualización anidada

Las VMs no arrancaban en Proxmox. Activé las extensiones de virtualización en cada VM de Hyper-V con la VM apagada.

VMs internas sin red

Suplantación de MAC

Los invitados no salían a la red a través del bridge. Habilité la suplantación de direcciones MAC en los adaptadores de Hyper-V.

HEALTH_WARN · clock skew

Sincronización horaria

Ceph avisaba de desfase de reloj entre monitores. Lo corregí configurando NTP (chrony) en los tres nodos.
